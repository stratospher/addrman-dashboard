An entry's nTime is when it was last refreshed, not when it arrived — every re-announcement overwrites it in place, and relayed addresses carry a 2 hour penalty. A peak that survives in a snapshot taken days later is a cohort that stopped being announced.

Network mix

Entries by network

Counts are whatever the addrman holds, not what is reachable — an entry exists whether or not this node has the transport configured. A network with entries but nothing in tried usually means the transport is off rather than that the peers are down.

Bucket references

new-table addresses by nRefCount

An address enters a new bucket chosen from its source's netgroup, so it gains a reference only when a fresh source announces it — up to ADDRMAN_NEW_BUCKETS_PER_ADDRESS = 8. References are what resist eviction and raise selection odds, so the distribution reads as how well corroborated your address set is. A flood arriving through few sources piles up at 1. Tried entries are excluded: MakeTried() clears them from every new bucket, so their nRefCount is 0.

Connection attempts

Connection history

Attempted is every entry with evidence of a dial: a recorded success, a recorded failure, or both. Successful and unsuccessful partition it, and adding the no-recorded-attempt remainder accounts for every entry in the table. That remainder is not quite "never dialled": Attempt_ only increments nAttempts when m_last_count_attempt < m_last_good, so at most one failure is counted per period of general connectivity — an address can have been dialled without the counter moving. And Good_ resets nAttempts to 0 on success, so it means failures since the last success, never a lifetime total.

Share of each table by nAttempts

Attempts since the last success. The 3 and 10 boundaries are ADDRMAN_RETRIES and ADDRMAN_MAX_FAILURES.

Why entries are terrible

Bars count each arm independently, so an entry satisfying two is counted twice and the bars can exceed the total. The table adds the first-match column, which does sum to it. The one arm not evaluated is the m_last_try <= 1min exemption — m_last_try is memory-only and reads as 0 from a file, so it can never fire here; on a live node it would only spare entries tried in the last minute.
